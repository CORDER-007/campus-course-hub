# 04 系统架构设计文档（初稿）

## 1. 总体架构

系统采用四层结构：

```text
页面层：HomeView / CoursesView / ScheduleView
    ↓
组件与交互层：导航布局、课程卡片、统计卡片、课表网格、筛选工具栏
    ↓
状态与数据层：Pinia course store + 本地 courses 模拟数据 + localStorage
    ↓
工程与部署层：Vite 构建、Hash 路由、静态站点部署
```

## 2. 页面结构

- `/home`：学习总览，展示学分、课时、课表摘要和提醒。
- `/courses`：课程中心，负责课程搜索、筛选、排序、选课和退选。
- `/schedule`：我的课表，负责周视图、已选列表和打印。

## 3. 数据模型

```js
{
  id, code, name, teacher, category, credits,
  room, weekday, dayLabel, periods, periodLabel,
  color, capacity, enrolled, description
}
```

`selectedIds` 只保存课程编号，避免将重复的课程完整对象写入本地存储。页面展示时通过课程编号重新映射到课程数据。

## 4. 状态流转

1. 用户在课程中心输入关键词或选择分类。
2. store 的计算属性生成过滤后的课程列表。
3. 用户点击加入课表，store 依次执行重复、容量和时间冲突校验。
4. 校验通过后写入 `selectedIds` 并同步到 `localStorage`。
5. 首页统计和我的课表通过计算属性自动更新。

## 5. 关键规则

- 重复课程：课程编号已存在时不重复添加。
- 满员课程：`enrolled >= capacity` 时不允许选课。
- 时间冲突：同一 `weekday` 和 `periods` 的课程不能同时选择。
- 退选：从选课编号数组移除，并同步持久化。

## 6. 部署结构

```text
源码 → pnpm build → dist 静态资源 → 静态站点托管平台
```

线上地址和 Git 远程仓库地址应在实际部署后填写，不使用样例中的虚构地址。
