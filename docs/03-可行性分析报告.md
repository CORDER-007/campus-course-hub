# 03 可行性分析报告（初稿）

## 1. 项目背景

高校学生在选课期间需要在多个页面之间确认课程信息、时间安排和学分进度。课程表与选课系统将这些信息集中到学生门户中，减少重复查询，并通过前端规则提示降低时间冲突风险。

## 2. 用户与需求

目标用户为需要查看课程、完成选课和规划学分的在校学生。系统需要提供课程浏览、检索、分类筛选、选退课程、周课表、学分统计和本地保存等能力。

## 3. 技术可行性

Vue 3 适合组织页面组件与响应式状态；Vite 提供较快的开发启动与构建能力；Pinia 将选课数据和业务规则集中管理；Element Plus 用于消息提示等基础交互；浏览器 `localStorage` 能满足无后端演示阶段的数据持久化需求。

## 4. 时间与资源可行性

系统采用本地模拟数据，不实现真实登录、数据库、支付和后端 API，减少接口联调成本。页面范围控制为总览、课程中心和我的课表三个主页面，适合单人一周完成，并能覆盖 Vue 组件化、路由、状态管理和工程构建。

## 5. 复杂工程问题约束

### 5.1 选课时间冲突

课程通过 `weekday + periods` 表示上课时段。Pinia 在选课前查找已选课程，如果星期和节次同时相同，则阻止选课并返回冲突课程名称。

### 5.2 跨屏与可用性

桌面端使用侧边栏和多列卡片；窄屏下自动收起侧边栏、改为单列课程卡片、允许课表横向滚动。主要按钮具备清晰文字和状态色，空数据场景提供继续操作入口。

### 5.3 数据刷新恢复

成功选课和退选后立即写入 `localStorage`。应用初始化时读取保存的课程编号，再从本地课程列表恢复完整课程对象。

## 6. 风险与备选方案

- 真实教务数据接口不可用：使用本地模拟数据完成前端验收。
- 依赖下载失败：保留准确的安装命令和版本要求，使用 npm 作为备用包管理器。
- 部署平台配置复杂：使用 Hash 路由和相对资源路径降低静态部署风险。
- 需求继续扩张：不加入真实认证、后台管理和成绩系统，确保核心流程稳定。
